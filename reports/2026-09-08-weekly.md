## Your two requests from last week

**1. Ingesting research papers: done and running.** The pipeline reads a paper's PDF (PyMuPDF
text layer), splits it into a verified structure (front matter, body, sections, references), and
turns it into entities and facts, each fact carrying a verbatim quote located in the text. Tested
end to end on five papers, Zep first (see the attached example). Because the papers are licensed,
they live in a private dataset; the public dataset withholds their text and carries a hash and URL
to rebuild it.

**2. Backend and embedding model: decided.**
- Backend: SQLite, a single file with no server. The document's full text is stored once, and
  every unit and every fact quote is a character range into it, so any claim resolves to its exact
  source text with one slice. Per-document JSONL "packages" are the write-ahead log the database is
  built from; a public database (text withheld only where a license requires) and a private one
  come from the same build.
- Embedding model: bge-small-en-v1.5 (384 dimensions) run locally through fastembed. CPU only, no
  PyTorch, downloaded once then fully offline, and swappable behind one interface. Chosen because
  the end product must run on a user's own machine offline, and at this scale a 384-dimension vector
  with brute-force exact search is one matrix multiply, so a larger vector buys nothing.

## Note on tooling
Extraction, ingestion, the SQLite store, and the evaluations all run on Kaggle. SQLite is a file, so
there is nothing to host; retrieval uses brute-force search, so it needs no database extensions.
